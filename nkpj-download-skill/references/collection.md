# 三部分采集与附件

## 操作边界

- 查询结果只用于筛选单位和打开「查看明细」。不使用查询结果中的「批量下载报告」「批量下载附件」或其他批量操作，不导出系统报告文档，不把导出文档压缩包作为交付物。
- 只进入每家单位明细的「基本信息」「评价指标打分」「补充说明」。不访问其他页签或菜单。
- 附件仅在「评价指标打分」页面按题处理。逐题打开「查看附件」，等待清单完成加载，再按弹窗清单核对和下载。题面上的附件名称或上传入口不能单独作为“无附件”的依据。

## 三部分采集

- **基本信息**：保留页面实际显示的分组、行列、字段值、空值和预填值。核对单位名称与代码。
- **评价指标打分**：完整展开四个大类的系统目录，按目录逐项读取，并将项目数与页面总数对账。保存层级、项目标题和指标题干。评分题读取实际分值（包括 0 分），未读到分值时记「未取得」。适用性题单独读取实际选中的「适用」或「不适用」，无法确认时记「适用性待核对」。忽略必填星号、灰色解释、扣分规则和上传说明。
- **补充说明**：按页面显示采集文本、表格、字段值和明确的空值。不要根据其他模块或历史材料补写解释。
- 项目标题分层保持与系统目录一致。若切换项目后目录项、正文或得分对应关系不确定，停止该项并回到可见界面核对，不按顺序猜测。

## 评价指标页附件

- 逐题打开「查看附件」，等待弹窗加载停止。若弹窗显示分页，逐页读取；只有加载完成且表格明确为空，才记录「未上传」。加载超时或状态不明，标为「附件清单待核」。
- 按弹窗清单逐件下载，不使用查询结果的批量附件下载。记录原文件名、所属单位、项目、题目、文件大小和 SHA-256；文件按单位保存在本地 `attachments/`。
- 优先提取可靠文字层。需要 OCR 时，优先由当前模型逐页识读；模糊页放大或纠偏后重读。保留页码及逐页纯文字，不确定内容标记待复核，不猜补。逐页核对印章，HTML 只显示盖章情况、盖章单位和与填报单位是否一致。
- 只有原件清单、下载文件和本地附件数可逐项对应，才将附件采集标为完整。附件读取或 OCR 失败应在 `verification.json` 写明题目与原因。

## 页面采集辅助

当前页面 DOM 与已验证选择器匹配时，可使用 `scripts/evaluation_list.js` 获取名录，并使用 `scripts/evaluation_detail.js` 通过可见界面采集三部分。脚本只在评分页逐题打开附件清单和下载单件附件，不应在列表页调用任何批量下载操作。通用 Agent 也可按同一范围通过可见界面采集。

在已登录的 BrowserSkill 会话中运行名录函数，把返回的 `value` 原样保存到 `source/名录.json`。返回列表并运行：

```text
python -X utf8 scripts/collect_browser.py "批次目录" --session "浏览器会话编号" --downloads "浏览器实际下载目录"
```

可以用 `--limit 1` 试采一家，或用 `--unit 单位代码` 指定单位。采集器核对名录的表头与正文列，并按项目保存进度。同一上报版本下，已归档附件通过条目信息和本地哈希核对后可复用。浏览器应使用本次采集专用的下载目录，避免其他窗口并行下载。逐件点击后确认唯一落盘文件，再继续下一件。若下载结果不明，先核对浏览器下载记录和当前页面。

独立复读时运行同一命令并加 `--verify`，省略 `--downloads`。只有回到同一查询范围、名录行上报时间未变时，才对照三部分及逐题附件进行复核。脚本记录每次独立复读的状态。最近一次复读未完成时，旧快照仍可查阅，本次核验状态标为待复核。确认差异后回源补采，并在校验记录中保留差异。
