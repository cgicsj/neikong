# 下载后校验

## 取得独立的网页对照

1. 查询时保留该批次的筛选口径、原始名单及顺序。逐主体核对年度、名称、单位代码、主体类型和系统可见的报送版本或时间。将界面主体类型统一记为「基层单位」或「汇总部门」，代码保留前导零。版本不可见时在两份记录中将 `report_version` 明确写为 `null`，复核时重新打开同一列表行并逐项对照两个页签。复核发现报送版本或可见内容在采集期间发生变化时保留旧证据，重新采集并核验同一版本。
2. 下载后、最终关闭明细前，再从网页读取两个页签，保存为单位目录的 `source/portal-check.json`。独立读取已加载的显示值、条件展开内容、表格所有相关行列和逐题附件列表（含分页）。同名题目用页签、层级、表格行列和页内顺序定位。复核文件不得从 `record.json`、HTML 或下载包反推。加载失败、值辨认不清、附件列表不可读等情况写入 `issues`。
3. 网页复核文件沿用[归档格式](archive.md)的身份和 `sections` 结构。顶层要有 `year`、`unit_name`、`unit_code`、`entity_type`、`report_version`、`rechecked_at`（实际复核时间）和 `sections`。前五个身份字段用字符串，版本不可见时用 `null`。采集记录的 `captured_at` 写本次开始读取明细的时间，复核时间不得早于采集时间，两者均用带时区的 ISO 8601 格式，如 `2026-11-21T09:00:00+08:00`。
4. 每个页签保留 `title`、`status` 和全部 `fields`。每项保留 `path`（层级或行列的字符串数组）、`label`、`value` 和 `attachments`。两次读取按同一规则记录显示值、选项顺序和空白状态。确认没有附件时登记 `attachments: []`。网页附件每条至少保留原名 `name`，能获取时保存系统附件 `source_id` 和精确的 `size_bytes`（仅在来源明确提供精确字节数时写整数）。

## 确认原件和识读覆盖

- 按逐题附件登记对账，保留列表顺序及每次下载的来源。`record.json` 记录同一 `report_version`，每份附件保存网页文件名和取得的 `source_id`。用界面标识、附件所属题目和列表顺序定位实际下载；批量包无法唯一匹配时回原题逐件下载。每条附件登记使用独立的本地路径，即使原名或字节相同。不能确认归属的文件保留并标记待核。批量包及下载来源记录保存在 `source/`，`attachments/` 仅存待链接的原件。
- 下载完成后，用对应格式的阅读器或解析器打开原件，排除空文件、错误响应、登录页和损坏文件。确认可读后写入 `original_opened: true`，并计算本次下载原件的 `sha256`。续跑和后续核验比对该值，发现变化先查明来源；只有有证据的重新下载才更新哈希。
- 从原件独立枚举 `content_units`，例如 `["第1页", "第2页"]`、工作表名列表，或无法稳定分页的文档使用完整章节定位。`text_parts` 的 `location` 逐一与之对应，确认该单元无正文时记录空字符串及 `blank: true`。全件识读并对照原件后写 `text_status: "全文已提取"`。识读缺页或局部无法辨认时保留实际状态和位置。只有逐页或逐工作表检查印章后，把实际检查的定位写入 `seal_checked_locations`，同时保留 `seal_coverage` 和逐枚印章记录。章名待确认时保留原结果；确认章名与填报单位不一致时如实显示差异。

## 校验与交付

从技能目录执行以下命令。脚本会在单位目录写出 UTF-8 的 `verification.json`，包括校验时间、状态和差异。缺少旧档的网页复核记录时，回源后再验证，禁止从旧档补造对照。

```text
python -X utf8 scripts/verify_unit.py "单位目录" --write-report
```

脚本逐项对照身份、页签、题目、填报值和附件清单，校验原件路径、哈希及识读覆盖记录，并用同一生成器核对 `index.html` 是否与当前记录一致。退出码 `0` 表示自动检查通过，`1` 表示有缺项、差异或校验材料无效。原件归属、正确打开、页数和识读准确性仍需依据现场网页与原件确认。用浏览器离线打开成品，检查两页签导航及有附件时的原件链接。发现差异先回到对应网页或原件确认，修正后重新生成并复验；保留无法解决的差异和证据。

批次交付前按原查询顺序逐行对照名单，核对目标数、归档目录及本次生成的 `verification.json`，检查重复、错配、漏归档和总目录链接。分别标明「校验通过」「待复核」和「未采集」。待复核项注明单位、页签、题目、附件及差异原因。确认的网页与附件内容差异（例如统计数不同）保留两边原值和出处，列为审核提示。`issues` 只登记未解决的采集或核验缺项。批次或单位缺少源证据时不得标为校验通过。校验记录含填报内容，只随归档保存在用户指定位置。
