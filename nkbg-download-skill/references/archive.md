# 单位归档格式

在批次目录内为每单位建目录，例如 `2025_示例单位_A01/`。保存 `record.json`、`attachments/` 内的附件原件及生成的 `index.html`。可在 `source/` 保存清单和原始下载包。重采有修改的报送记录时另建版本目录。

将实际读取的数据按以下结构写入 UTF-8 JSON。保留两页签及字段实际顺序。字段的 `path` 可保存逐级标题和表格的行列定位。`label` 保存实际题目，`value` 保存题目对应的填写或选中值，每个字段直接携带其附件。

```json
{
  "year": "2025",
  "unit_name": "示例单位",
  "unit_code": "A01",
  "entity_type": "基层单位",
  "captured_at": "2026-11-18T20:00:00+08:00",
  "sections": [
    {
      "title": "基本信息录入",
      "status": "已采集",
      "fields": [
        {
          "path": ["单位基本信息"],
          "label": "签章扫描件报送",
          "value": "是",
          "attachments": [
            {
              "name": "封面.pdf",
              "path": "attachments/001-封面.pdf",
              "download_status": "已下载",
              "text_status": "全文已提取",
              "text_parts": [
                {"location": "第1页", "method": "当前模型识读", "text": "此处填写实际识读全文"}
              ],
              "seal_status": "有章但单位待复核",
              "seal_coverage": "已检查1/1页",
              "seals": [
                {"location": "第1页右下方", "organization": "待复核", "inscription": "此处填写印面可辨认的文字"}
              ]
            }
          ]
        }
      ]
    },
    {
      "title": "单位内部控制情况",
      "status": "未采集",
      "fields": []
    }
  ],
  "issues": ["第二页签未采集的实际原因"]
}
```

- 页首提供两页签的页内导航，方便查找及连续阅读。基本信息按表单分组并排展示，窄屏自动换行。内控情况按原表的章节、小节和题目顺序展示，每组标题显示一次。以实际的 `path` 保留表格的行列定位。填写值、选中项、预填或计算值直接显示在对应题目下，原件链接和按页直接显示的附件全文紧随对应题目。HTML 省略「值」及逐题来源标签。
- `value` 保存实际文本、数字、布尔值或按界面顺序排列的选中项数组。界面有选项文字时保留显示文字，例如「否」或「不适用」。固定标题和纯附件项可用 `null`，已确认空白和未选分别写「空白」和「未选」，数字 `0` 作为实际值保留。条件未展示或不可读时记录实际情况。 `attachments` 可省略。漏下载的附件保留其名， `path` 为空，并在 `download_status` 写明实际原因。存在待核关联的原件放入所属页签的「题目待核」字段。页签也无法确定时另列「附件所属页签待核」。
- 每个附件要有 `seal_status` 和 `seal_coverage`。`seals` 中每枚章记录 `location`、`organization` 和 `inscription`。`text_parts` 按页或工作表排列，HTML 展示页码或表名和正文，识读方式只保存在采集记录中。成功识读时不显示方法或“已识读”状态，失败、缺页或未完读时才通过 `text_status` 提示。原件链接有效且下载已确认时，省略下载状态。附件可另记哈希、原包路径及获取时间。
- HTML 每份附件的印章信息仅展示盖章情况、盖章单位和与填报单位是否一致。多个不同的盖章单位和结果按相同顺序列出。比对使用印面可确认的单位全称，统一空白和全半角，并允许忽略填报单位名称末尾的系统「（本级）」标记。印面必须支持完整名称，公章等已知章类和末尾编号可与单位名称分开辨认。仅识别到单位名称的一部分或存在无法解释的后缀时显示「无法判断」。确认未见印章时，比对显示「不适用」。印面原文、印章位置、检查覆盖及已有 OCR 对照底稿保留在采集记录中。
- 将批次范围、各页名录及处理状态保存在批次根目录，生成总目录 HTML 链接各单位材料册。记录包的获取时间、页面报送状态或时间，以及无法取数的单位或字段。

使用当前环境可运行的 Python 3 执行以下命令。脚本只消费已经采集及识读的数据。

```text
python scripts/build_unit_html.py <单位目录>/record.json
```

脚本输出同目录的 `index.html`。从页面抽查原文、选项及附件题目对应关系。将整个单位目录一起移动，浏览器即可从页面打开相对路径链接。生成器会检查记录中声明的附件路径是否位于单位目录的 `attachments/` 内，且存在非空原件。源数据更正后可重新生成 HTML。
