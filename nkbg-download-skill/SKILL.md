# 基层单位内控编报下载

在用户已登录的财政部统一报表系统中只查看和下载。默认范围为当前年度任务下账号可见的全部基层单位，按用户指定调整年度、下级范围和上报状态。禁止触发退回、保存、提交或审核标记。

## 使用前准备

- 用户先在 Agent 可操作的浏览器中登录财政部统一报表系统，并确认账号能打开目标年度、目标范围内的「查看明细」。如需单位内网、VPN 或登录验证，先由用户完成接入。会话失效时请用户恢复登录，再继续采集。
- 启用可操作该浏览器会话的浏览器 Agent 或自动化工具。开始时确认工具能打开目标明细、切换两个页签、读取表单及附件列表，并能把下载的文件保存到 Agent 可读取的位置。工具可使用当前平台提供的浏览器能力。
- 准备可读写的输出目录和 Python 3.9 或以上版本。完整识读还需要能打开或解析附件、渲染扫描页，并具备图像识读或中文 OCR 能力。遇到无法读取或辨认的位置，记录实际缺项。
- 仅做离线校验时，准备已有的 `record.json`、附件原件、`index.html` 和独立取得的 `source/portal-check.json`，可跳过登录和浏览器采集。缺少网页复核记录时按「待复核」处理。

## 查询与采集

1. 进入「下级报送纵览 → 内控报告报送纵览」，先清除旧的上报状态或标记筛选，再按用户指定设置本次条件。选择「单位类型 → 基层单位」并点「查询」。确认结果行的单位类型为「基层」或「基层单位」，结果仍混有汇总单位时重新筛选。
2. 登记筛选口径、总数和逐页名录。只给数量时按当前查询顺序取前 N 家并记录顺序。按报告年度、单位代码和主体类型识别记录，报送版本另记报送时间。
3. 逐行打开对应的「查看明细」，用单位名称、代码和主体类型核对身份。依次读取「基本信息录入」和「单位内部控制情况」，等待页签正文及附件数量加载完成。第二页签显示「部门内部控制情况」时，先核对是否误打开了汇总行。
4. 按界面顺序原样记录章节、题目、表格行列和值，包括文本框、富文本、下拉框、单选、多选、禁用控件、预填值和计算结果。选项保留显示文字。用户填写值与系统标题通过 HTML 层级、题目标题 `label` 和实际值 `value` 区分。
5. 每完成一个单位就保存采集记录和附件状态，按下文要求在关闭明细前获取网页复核记录，再返回列表。中断后按年度、单位代码、报送版本及附件清单续跑。没有明细入口、无权限或加载失败的单位保留在名录并记录原因。

首次批量使用前，先完成一个单位的抽查，完整跑通两个页签的采集、附件下载和下文的校验流程。之后仍以每次现场可见控件为准。

## 附件与输出

对两页签逐题下载全部附件并按[附件下载与识读](references/attachments.md)提取全文和识读印章。需要 OCR 时先用当前模型逐页看图，模型无法接收图像或重读后仍不能辨认的区域，再用本地中文 OCR 补读。表格、流程图、手写文字和印面均需核对。

每单位建立独立目录，保存 `record.json`、`attachments/` 和 `index.html`。按[归档格式](references/archive.md)生成页面，沿用实际页签、章节和题目顺序。每题直接显示值及附件链接，附件全文直接展开。印章信息只显示盖章情况、印面确认的盖章单位、与填报单位是否一致。

## 验收与收尾

- 按[下载后校验](references/verification.md)独立复读网页，逐主体核对身份、报送版本、两页签字段、附件和成品 HTML。保存 `source/portal-check.json`，生成 HTML 后运行校验脚本并保存本次 `verification.json`。
- 将批次名录与归档及校验结果逐行对账，批次总目录按「校验通过」「待复核」「未采集」标记。差异回源确认后复验，未解决的缺项保留具体位置及原因。
- 正常完成、失败或中断后都先保存和核验成果，再关闭本次打开的明细、预览、临时编辑器和自动化标签页。先处理「另存为」等模态对话框，确认关闭结果。保留用户原有标签页、窗口和登录状态。
- 无法关闭或只能保留部分成果时，说明具体窗口、保存状态和缺项，不把未核验内容标为完成。
